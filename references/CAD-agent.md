# 面向 CAD Agent 建模规划的训练数据集构建与模型微调

> 原项目说明快照：用于交代研究目标。正文中已有模块、数据和候选描述的陈述不等同本次独立验证成果；已实际完成的评测、尚未完成的 P 接口对照与 student 训练，见[阶段汇总](../reports/2026-10-28-CAD.md)。

## 1. 项目背景

本项目希望让用户通过自然语言描述几何形状、尺寸和空间关系，由Agent自动完成参数化CAD建模，并在失败时根据执行反馈进行修正。

目前已经搭建了一套基于大语言模型和CadQuery/OCC的CAD Agent。本次实习不从零开发系统，而是重点构建能够训练T2建模规划能力的数据集，并在此基础上开展基座模型的针对性微调与验证。

核心目标是：让模型在获得几何事实规格后，更稳定地输出符合当前API、对象引用和几何要求的可执行建模计划。

## 2. 已有工作基础

现有系统包括四个阶段：

| 阶段           | 当前职责                                                                               |
| -------------- | -------------------------------------------------------------------------------------- |
| T1：需求解析   | 将自然语言整理为几何事实规格，包括实体、轮廓、尺寸、坐标与关系；不强制预先指定建模历史 |
| T2：建模规划   | 根据规格选择构造方式，输出包含API、参数及对象引用的类型化计划P；代码将P编译为执行指令G |
| T3：几何执行   | 通过封装的CadQuery/OCC接口构建模型，导出STEP/STL并记录真实执行结果                     |
| T4：验证与修复 | 综合内核测量、需求绑定及视觉反馈，判断结果，触发有界局部修复                           |

此外，系统已经实现：

- **中间对象状态表**：由代码记录草图、曲线、闭环、轮廓和实体的身份、归属、版本及替代／消耗关系，供规划和修复查询。
- **结构化接口与错误反馈**：检查参数、对象类型、引用和依赖，记录失败步骤，减少无效重复尝试。
- **评测工具**：区分有效CAD生成、需求验证和离线几何质量，支持原生体积IoU、CD、HD等指标。
- **数据基础**：已整理Fusion 360样本与参考模型，并由Qwen3-32B生成200条保留已知尺寸的几何结构描述。目前这批描述尚未独立语义复核，只能视为候选输入。

现有系统是参考CADDesigner、ReliCAD等工作的独立实现，不等同于官方代码或完整复现。已经验证部分结构化输入下的下游执行能力，但自然语言端到端生成仍不稳定，不能将已有模块实现等同于任务已解决。

## 3. 当前主要问题

**T2的建模计划不够稳定。**
即使规格包含必要信息，模型仍可能混淆草图与轮廓、选择错误材料区域、遗漏构造步骤或引用错误实体。

**失败反馈不一定能有效落地。**
修复可能重复同一错误，或者修改范围过大，引入新的问题并增加耗时。

**生成质量与验证结果需要分开分析。**
有效CAD不一定符合需求；T4无法验证也不一定意味着模型建错。参考模型的离线几何指标不能被送入生成器充当答案。

## 4. 实习目标与主要任务

### 任务一：构建并验证建模计划数据集

优先利用已有Fusion 360数据，其次使用DeepCAD／PointerCAD中能够准确转换的样本，参考HistCAD的历史、约束与实体引用组织方式。未获得的HistCAD官方集合不能写成已拥有的数据；自行加工的Fusion数据也不能冒称官方HistCAD。

构建过程：

1. 从源历史确定几何事实，生成规范化规格D，保留曲线、坐标系、尺寸、材料区域和对象关系。
2. 将可转换的构造历史转换为计划P；需要LLM辅助的部分仅作为候选。
3. 编译P并真实执行，检查类型、引用、闭环、内外轮廓和最终实体等。
4. 将生成几何与可靠参考模型比较，并检查D中的需求是否被满足。
5. 合格样本进入正例集；失败、信息不足和无法验证的样本单独保存，不能直接作为正确标签。

不要求预测计划与原历史逐步相同：不同构造方式只要满足相同规格并经验证，也可以作为正例。训练时可以使用源历史构建标签，但独立评测时不能把参考历史、标准P或参考模型送给生成器。

优先覆盖：简单拉伸、多轮廓与孔、多实体、Boolean组合、跨操作对象引用及长计划。Revolve、Fillet、Chamfer等只有在来源或受控生成样本足够、且验证可靠时再加入

### 任务二：整理修复轨迹并开展微调

参考RA-CAD
同时收集“规格D—失败P—实际执行反馈—局部补丁—修正P—复验结果”，作为后续修复能力训练数据。错误原因应区分日志可证事实与模型推断；只有复验成功的计划才能标成成功修正。

## 5. Related Work

### CADDesigner：工具化CAD生成与视觉反馈

CADDesigner通过ECIP组织建模上下文与操作，结合需求分析、CAD生成和迭代视觉反馈。它是本项目早期工具接口与Agent闭环的重要参考。

建议重点阅读：ECIP如何表达建模对象与上下文，以及视觉反馈如何参与生成改进。

[CADDesigner: Conceptual CAD Model Generation with a General-Purpose Agent](https://arxiv.org/abs/2508.01031)

### ReliCAD：规格、内核证据与反馈修复

ReliCAD显式建模设计意图，生成约束感知的参数化指令，调用CAD内核并记录运行证据，通过验证反馈定位错误和迭代修复。它与本项目当前“规格—计划—执行—验证”的思路最直接相关。

建议重点阅读：如何区分设计要求与构造决策，如何利用真实执行证据支持验证和修复。本项目具体JSON接口、CadQuery封装和验证器属于自己的实现，不能直接视为论文原版。

[ReliCAD: From Uncertain LLM Generation to Reliable Parametric CAD Modeling](https://arxiv.org/abs/2609.22325)

### Text2CAD：文本粒度与参数化建模序列

Text2CAD研究从不同详细程度的文本生成参数化CAD序列，并构建文本标注流程。它有助于理解输入描述粒度、训练数据与建模序列之间的关系。

建议重点阅读：抽象描述与详细几何描述的差异，以及如何设计文本—CAD配对数据。不要将特定数据集上的操作范围等同于完整工程CAD能力。

[Text2CAD: Generating Sequential CAD Models from Beginner-to-Expert Level Text Prompts](https://arxiv.org/abs/2409.17106)

### DeepCAD：CAD构造序列与数据基础

DeepCAD以CAD操作序列表示模型，并提供相关数据集，为参数化重建和数据组织提供基础。但构造历史不等于自然语言需求，也不能直接充当本项目T2计划标签。

[DeepCAD: A Deep Generative Network for Computer-Aided Design Models](https://arxiv.org/abs/2105.09492)

### HistCAD：实体引用、约束与可执行建模历史

HistCAD当前论文围绕带实体引用草图约束的参数化历史，评估模型能否复现初始几何、完成尺寸编辑并保持未修改要求。它对本实习的价值，是说明训练数据应保存对象关系、约束和可重建证据，而不仅是一段自然语言加一个最终网格。

需要注意：HistCAD历史／约束表示不等于本项目的P接口，其约束预测与可编辑性任务也不同于D→P规划。应借鉴数据组织及执行验证，不能直接把全部历史字段当作模型输入，制造推理答案泄漏。数据权限和实际可获取范围需分别确认。

[HistCAD: Constraint-Aware Parametric CAD Histories for Evaluating Editability](https://arxiv.org/abs/2602.19171)

### RA-CAD：从代码基础能力到执行反馈训练

RA-CAD采用Generate—Execute—Critique—Rewrite循环，将执行后的critique作为显式策略行为。其CAD Code Bootstrapping先通过监督微调建立CAD代码能力，Feedback-Driven Agent Optimization再通过轨迹级GRPO联合优化代码与critique。

对本实习的启发是先收集经验证的正确构造数据，再收集完整修正轨迹。RA-CAD主要生成CAD代码，本项目训练类型化计划P，不能直接照搬输出标签。其rewrite也不能未经核实就称为本项目这种受保护局部补丁；本期不承诺复现其强化学习训练。

[RA-CAD: Learning Post-Execution Critique for State-Aware Text-to-CAD Generation](https://arxiv.org/abs/2608.05714)

优先阅读顺序：ReliCAD（目标架构）→ HistCAD（数据与执行验证）→ RA-CAD（训练路线）→ CADDesigner（接口背景）；Text2CAD与DeepCAD作为文本和序列数据补充。上述HistCAD介绍依据当前arXiv版本，具体使用旧版方法时应固定论文版本，不能混用不同版本的结论。
