# 金融材料小试：题目格式与 Codex + Luna 解题方式

具体题目见：[四道真实案例：输入图片、标注答案与 Luna 原始回答](CASE_EXAMPLES.md)。

## 1. 当前结论

目前已生成并执行 **30 道题**，包括 **18 道单文档判断题、12 道原改对比题**，来自 **21 组不同原件**。

解题方式是：**每题启动一个新的 Codex 会话，提供固定题面和整页图片，由 `gpt-6-luna` 输出结构化答案。实际没有发生多轮工具探索。**

按本次临时内容完成口径，合计为 **52.5/100**。该分数对应当前整页看图直答配置，不是正式 benchmark 准确率，也不代表使用高分辨率、OCR、计算和复核工具后的能力上限。

## 2. 数据与输入形式

源站提供的是原件、修改件及其核查标注，包括修改字段、前后值、物理页码、位置框和核查依据。本次从这些标注中整理固定题面和答案对照。

模型实际收到的是：

- 单页或原改各一页的整页图片，最大边通常约为 1300px。
- 固定中文任务说明。
- 约束答案格式的 JSON Schema。

模型没有收到原始文件名中的修改提示、答案框、后台标注或历史检测结果。图片采用中性文件名，例如 `page.jpg`、`page_a.jpg` 和 `page_b.jpg`。

**当前所有题目均为图像输入。** 金额、日期、账号等文本内容也是从图片中读取；没有额外提供 OCR 纯文本、原生 PDF 或 PDF 元数据。多页源文件只提供本题选中的页面，不要求判断未提供的页面。

同一轮中的修改版和原版本对照会共享来源；不同问题使用独立会话。首轮 10 题与新增 20 题的原件来源不重叠，但尚未审计所有主体、模板和近重复关系。

## 3. 题目格式

### 3.1 单文档判断：18 题

其中 9 题提供修改版，9 题提供对应的原版本作为对照。单题内只展示一张图片，不告知版本身份，也不提供原件参照。

核心问题：

> 仅检查附件中的这一页，判断是否有充分证据怀疑关键业务内容被编辑。结合可见的局部图像痕迹与金额、日期、字段关系，给出具体证据；证据不足时可以保留判断。

题面特别约定：

- 正常拍照、压缩、扫描或软件导出本身，不能直接证明业务内容被改。
- 金额计算允许不超过 0.02 元的分位舍入误差。
- 不要求凭空恢复编辑前的数值。
- 未发现编辑证据不等于材料业务真实。

输出结构如下，示例中的值仅说明格式：

```json
{
  "decision": "suspicious",
  "evidence": [
    {
      "page": 1,
      "field": "税率与税额",
      "bbox": [0.70, 0.40, 0.90, 0.50],
      "observed_value": "可读数值",
      "reason": "可以直接核验的简短依据"
    }
  ],
  "summary": "结论"
}
```

`decision` 允许三个取值：

| 取值 | 含义 |
|---|---|
| `suspicious` | 发现足以引起内容编辑疑虑的证据 |
| `no_clear_evidence` | 未发现明确证据，不代表确认真实 |
| `insufficient` | 当前信息不足，保留判断 |

`bbox` 是相对于附件整张图片的归一化 `[x1, y1, x2, y2]` 坐标。最多报告 4 处证据，无异常时可以为空。

实际题面：[单文档题面](prompts/single.txt)。

### 3.2 原改对比：12 题

输入是同一来源材料的编辑前页 A 和编辑后页 B，明确告知两张图的顺序。

核心问题：

> 找出两页之间关键业务字段的内容差异，给出字段、前后值和两侧位置；区分内容变化与旋转、压缩、清晰度、裁切或版式差异。

输出结构如下，示例中的值仅说明格式：

```json
{
  "changes": [
    {
      "field": "签署日期",
      "before": "A 中的值",
      "after": "B 中的值",
      "page_a": 1,
      "page_b": 1,
      "bbox_a": [0.10, 0.80, 0.40, 0.85],
      "bbox_b": [0.10, 0.80, 0.40, 0.85],
      "reason": "短依据"
    }
  ],
  "summary": "结论"
}
```

两侧坐标分别相对于各自整张图片；`page_a`、`page_b` 使用附件内的页号 1，不是源 PDF 的物理页码。最多报告 8 处变化，无法辨读时需要明确表示不确定。

实际题面：[原改对比题面](prompts/paired.txt)。

## 4. Codex 实际怎样解题

### 4.1 配置与流程

| 项目 | 本次设置 |
|---|---|
| 执行器 | Codex CLI 0.164.0 |
| 指定模型 | `gpt-6-luna` |
| 请求的 reasoning effort | `medium` |
| 会话 | 每题新建独立 ephemeral 会话 |
| 题目尝试次数 | 每题 1 次 |
| 并发 | 最多 2 题 |
| 每题超时 | 240 秒 |
| 沙箱 | `read-only` |
| 输出 | JSON Schema 约束的结构化答案 |
| 反馈重试 | 未根据评分反馈修改提示词或重新作答 |

实际使用 `codex exec`，通过 `--image` 附图、标准输入传入题面，并用 `--output-schema` 约束格式。原始结果保存在每题的 `runs/Qxx/` 目录。

流程为：

```text
固定题面 + 整页图片
        ↓
新的 Codex + Luna 会话
        ↓
结构化答案
        ↓
后台对照已有标注，核对内容和位置
```

题目目录中的 `AGENTS.md` 要求只使用当前题面和图片，不读取父目录、其他题目或答案文件，不联网、不安装包、不调用其他 Agent；允许查看附件图片。

### 4.2 一次作答与多轮探索的区别

日志中共有 **30 个会话、30 个用户输入轮次**。所有记录到的输出项均为 `agent_message`，没有命令执行、OCR、计算脚本、图像工具或其他工具调用。

因此，本轮的实际行为属于**整页看图直答**。没有形成“浏览 → 选择区域放大 → OCR → 计算 → 复核”的工具循环，也没有翻阅其他页面。

其中 Q26 输出过一条进度说明，再输出最终答案；这不构成工具探索。

准确表述是：**每题一个独立 Codex 任务、一次用户输入、一次尝试；实际无工具探索。** CLI 事件日志不能证明每题恰好只对应一次底层 API 请求，因此不把“一个输入轮次”直接等同于“一个 API 请求”。

执行脚本、完整输入和逐题日志保留在本地，本公开版本不包含内部整页材料。

## 5. 评分口径与结果

本次使用探索性的“内容完成分”，每题满分 10 分：

- **单文档修改版**：需要报警，并给出命中实际修改目标的有效证据，计 10 分。只写“可疑”但理由无关或自相矛盾，不计正确。
- **单文档原版本对照**：回答 `no_clear_evidence` 计 10 分。
- **保留判断**：按解题完成口径计 0 分，但不等于该判断在事实或风险控制上不合理。
- **原改对比**：按正确恢复的已标注字段比例给分。例如 4 处找对 3 处，得 7.5 分。账号等字段要求前后值精确，日期空格、常见数字格式可以归一化。
- **位置框**：单独计算与标注框的 IoU，尚未纳入上述内容分。

评分由当前 Codex 对照已有标注核对，包含程序比对和结果审查，不是独立人工复标。首轮评分口径在扩展轮模型调用前固定；新增题面的措辞与首轮相同。

| 范围 | 题数 | 内容完成分，折合百分制 |
|---|---:|---:|
| 首轮 | 10 | 47.5 |
| 扩展轮 | 20 | 55.0 |
| 合计 | 30 | **52.5** |

合计结果：

- 30/30 个任务完成，均产生可解析答案。
- 单文档的 9 份修改件中，2 份输出 `suspicious`，其中只有 **1 份**提供了有效目标证据；另有 1 份保留判断。
- 9 份原版本对照中，7 份未发现明确证据，1 份保留判断，1 份误报。
- 12 道配对题中，8 题至少找对一处已标注字段；总计恢复 **10/16 个**已标注字段。
- 找对字段内容不等于位置框正确，多处框有明显偏移。

几个诊断案例：

| 题号 | 现象 |
|---|---|
| Q01 | 税率被改为 11%，但模型只核对金额加总，漏掉税率与税额的矛盾 |
| Q03 | 税表第 27 行与分项相加相差 324 元，未报警 |
| Q11 | 明细金额为 `82222.96`，模型却用合计中的 `82264.96` 判断关系一致，掩盖了实际差异 |
| Q13 | 正确发现明细金额与合计、数量乘单价不一致，并命中目标字段 |
| Q15 | `decision` 写“可疑”，理由却都在说计算相符，未提供有效报警依据 |
| Q16 | 对原版本报出不存在的 110000 元计算差异；独立复算表内关系实际一致 |
| Q23 | 发现账号发生变化，但原值多读了一个 0，精确转写失败 |

## 6. 这些结果能说明什么

这轮支持继续研究几项能力：忠实读取局部数值、核对金融表格关系、发现细微字段差异，以及将答案正确定位到图像中。

但低分不能单独证明 benchmark 有效，当前仍有以下边界：

1. **分辨率与探索方式有限。** 当前使用整页显示图，未测试原生高分辨率、主动放大、OCR 或程序计算。
2. **部分单图的可判性未审定。** 把一个合法日期、资本金额或五级分类改成另一合法值，不一定留下单份材料即可证明的异常。需要区分可检测证据、真实编辑标签和业务真假。
3. **原版本不是业务真实性金标准。** 它只提供编辑前版本；没有独立认证交易、身份、登记信息等真实有效。
4. **标注范围不一定穷尽。** 目前按已核实字段评分，不把其他未标注位置直接判为假阳性；部分标注还含 LLM 辅助核查或历史待确认备注。
5. **仍是开发小试。** 站点预留成员身份尚未从公开接口解析，不能宣称这批题是干净的独立测试集，也没有用于训练或调参。
6. **材料类别需要清理。** 例如部分台账归为“网银”的图片，实际展示税务页面；正式数据集需要按真实页面内容复核分类。

## 7. 下一阶段：多轮工具探索对照，尚未执行

可以先保持相同题面和来源，增加一个允许工具探索的实验条件：提供原生高分辨率页面，允许模型自行旋转、选择区域放大、运行 OCR、编写计算脚本，并在固定时间与工具预算内复核后作答。

为区分提升来自哪里，最好分别比较：

| 条件 | 输入与操作 | 状态 |
|---|---|---|
| A：当前基线 | 约 1300px 整页图，实际直答 | 已完成 |
| B：高分辨率直答 | 提高图像分辨率，保持直答 | 未执行 |
| C：工具探索 | 与 B 相同的原始信息，允许主动放大、OCR、计算和复核 | 未执行 |

这样可以区分分辨率、读取能力和工具探索带来的收益。比较时应固定模型版本、effort、评分和数据来源，分别报告内容、证据定位、误报、保留判断以及耗时和调用成本。
