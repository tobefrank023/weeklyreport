# 2026-11-04 周报

本周从已有 RF rollout 中整理了六道真实仓库重构任务，重点看两件事：模型能否在较长的执行过程中完成复杂迁移，以及同一道题为什么会在不同运行中出现较大的评分差异。

找到的三个长轨迹案例分别来自 NEURON、HikoGUI 和 HighFive，主轨迹为 **335、332、227 轮**，三次运行的 rubric 均为 **1.0**，功能测试也全部通过、原始 reward=1。这些题分别要求统一跨语言的构建与加载契约、统一 GUI 事件传播接口，以及把隐式维度适配改为显式兼容性检查。它们的共同点是需要把一套规则迁移到多个调用方，同时保留约定的行为，适合用来观察完整的仓库级重构过程。

另外整理了 AMGCL、Elements 和 AWS SDK for C++ 三题。它们在 high effort 三圈中的 rubric 分别为 **1→0→1、0.727→1→0、0→0→0.909**。其中 AMGCL 第二圈功能测试通过但 rubric 为 0，第三圈两项都通过；Elements 和 AWS SDK 的高 rubric 运行则仍未通过功能测试。因此报告把 rubric、功能测试和原始 reward 分开呈现，避免把高 rubric 直接写成全面通过。圈间 Web 工具配置也有调整，目前还不能把分差全部归因为模型的随机波动。

下一步优先对比这些题的成功与失败 patch，再核对逐条 rubric，判断分差来自实现、结构要求还是评分噪声。当前已完成案例整理和历史记录核对，没有重新执行 rollout。

本周还完成了软件工程 Agent 中途错误建议评测的原型试跑：从真实错误轨迹整理六道开发题，按九个方法阶段迭代固定、重复、动态和受限视野用户。最新关注组实际收到五条消息，错误组首条后提前结束，尚未形成次数消融；目标错误在插话前已存在，因此不将其归因为建议。接下来先固定更早的插话点和各组统一的持续解题约定，再做独立任务上的重复验证。

公开金融文档方面，使用两份公开财报构造了两轮各10道题，加入跨页关系、单位变化和正常重述对照。Luna的临时内容完成分从基础轮95降为升级轮62.92；该结果属于同源开发小样，尚不是正式benchmark成绩。专题同时整理前期修改模式与公开case的对应关系，未覆盖类别单独注明。
